# Lecture 1 · SE Introduction
## Software
- = **programs + documentation**
- Product types
  - **Generic**: sold to many customers
  - **Custom**: one customer, built to their spec
- 3 ways to create: **develop new · configure generic · reuse**
- Role: economies of all developed nations depend on software
## Good software (4 attributes)
- **Maintainability**: must **evolve**
- **Dependability / Reliability**: **trustworthy**
- **Efficiency**: no wasteful use of resources
- **Acceptability**: understandable, usable, **compatible**
  - Compatibility (user): version, environment
  - Portability (system): move platforms with few changes
## Costs
- Boehm '81: software ~15% → **~90%** of total cost
- Software **> hardware**
- **Maintenance > development** (long-lived systems)
- **60% dev · 40% testing**
- Custom: **evolution > development**
- Goal: **cost-effective**
## Software Engineering
- **Engineering discipline**: theories, methods, tools
- Goals: **budget · on time · quality · customer needs**
- CHAOS 2020: **35% success · 46% challenged · 19% failed**
- Comparison
  - **CS**: theory, fundamentals
  - **SE**: practice, delivery
  - **System Eng.**: HW + SW + process (contains SE)
## Trends
- **Intelligent SE**: AI for SE · SE for AI systems
- **Low-code / No-code**: WordPress, Wix, Airtable, Shopify…
- **CI**: integrate code automatically and frequently
- **CD**: automatically build, test, release-ready
- **DevOps**: culture + practices + tools, shorter SDLC
- **Agentic AI**
  - Completion → chat → **agent** (goal, plan, tools, iterate)
  - Engineers: specify, review, verify, **remain accountable**
  - Risks: wrong code, security, license/IP, data leaks
## Software process
- = set of activities to develop / evolve software
- 4 activities
  - **Specification**: what + constraints
  - **Development**: design + code
  - **Validation**: is it what the customer wants?
  - **Evolution**: change with demands
- Process model = **simplified representation** from one perspective
  - Workflow: sequence
  - Data-flow: information flow
  - Role/action: **who does what**
- Generic models: **Waterfall · Iterative · CBSE**
## Professional ethics
- More than **upholding the law**
- 4 issues
  - **Confidentiality**
  - **Competence**: don't accept work beyond it
  - **IP rights**: patent, copyright
  - **Computer misuse**
- ACM/IEEE Code (8)
  - **PUBLIC** · Client & Employer · Product
  - **JUDGMENT**: integrity, independence
  - Management · Profession · Colleagues
  - **SELF**: lifelong learning
